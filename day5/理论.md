## 理论

问题1: 什么是 **MCP**？MCP Server / MCP Client / Tool / Resource / Prompt 分别是什么？

答：MCP 是模型上下文协议，是AI应用接入外部工具的统一标准接口协议；

MCP Server : 把模型的能力包装成服务，可以提供给第三方（工具，数据，提示词的提供方）

MCP Client : 客户端，模型能力接入客户端 AI 应用的端侧，可以接入Server 发现工具列表，调用工具并拿结果。

MCP Tool : 可执行的功能（函数），模型可根据需要调用。

MCP Resource:  以“资源的” 的形式暴露，一般是可读的数据（文件，数据库内容）

MCP Prompt:  可以复用的提示词模版，Server 可以提供标准化的提示词模版给客户端使用。

---

问题2: 我们 Day 2 已经实现了原生 Function Calling，**MCP 和它有什么区别**？

答：Function Calling 是模型API 的内建能力，解决模型到你的应用代码着一层；

MCP 是解决AI应用到外部工具服务 这一层；工具是外部的，可以是任意的MCP Server 上的运行时发现。

总结： Function Calling 解决“模型如何表达调用的意图”；MCP 解决：AI应用如何发现并连接外部工具

---

问题3: MCP 解决的是**模型问题**还是**系统集成问题**？为什么？

答：解决的是后者，因为MCP 是应用层去集成各种系统：数据库，GitHub 等等的桥梁。

问题4: 为什么 MCP 对 Agent 生态有意义？
（想想：如果每个工具厂商都自己发明一套接口格式，会怎样？）

答：统一的标准对整个生态的沟通带来了沟通效率的提升，为agent的生态做出了巨大的贡献，如果每个工具厂商都自己发明一套接口格式，消耗的是开发者的时间和整个生态的混乱。非常的不利；
