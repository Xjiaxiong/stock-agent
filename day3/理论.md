## 理论

问题1: 什么是**短期记忆**和**长期记忆**？在 Agent 里分别指什么？举一个你自己的例子。

答：短期记忆指的是与 agent 的对话历史中上下文的容量，比如一般的代码 agent，指的是 200k 容量的上下文；长期记忆指的是即便过了多轮对话、换了不同的主题，它仍然记得你的个人偏好和编码习惯，几乎用个人偏好文档记录下来，每次对话的时候会先理解再决定，更聪明。

---

问题2: 什么是 **State（状态）**？为什么 Agent 执行多步任务时需要它？
（可以想一想：Day 2 里"分析宁德时代"调用了 3 个工具，结果全都堆在 messages 里，这样够用吗？）

答：State 本质是Agent的状态，Agent在调用多个工具，执行多步任务的时候会需要很多中间的状态数据，这个过程存在State是必要的，有了过程状态的衔接，才能更好的完成最终任务。

另外 Day2 里"分析宁德时代"调用了 3 个工具，结果全都堆在 messages 里，这样可能不够用，如果遇到复杂的状态管理，State的维护就不那么容易了，可能有更好的方式维护这个State， 但是我目前还不知道。

---

问题3: 为什么**不能**把所有历史对话全部塞进 Context？至少说两个原因。

答：
1，因为历史对话要占用内存空间，而内存空间是有限的，如果有太多历史对话，就会导致内存空间不够用，从而导致模型崩溃。

2，对于特定的任务来说，很多部分的历史对话其实无效的上下文，显得既不高效也不优雅。

3，成本上，token按量计费，历史上下文越长，每次请求就越贵。

4，质量上：长上下文里中间位置的信息容易被模型忽略，塞太多，反而抓不到重点。

---

问题4: **Memory 和 RAG 的区别**是什么？
（提示：一个存"关于用户/任务的过程信息"，一个存"领域知识"）

答：
RAG 是“检索增强生成”，把外部的信息切块、向量化，回答问题时先检索相关片段，再注入上下文。Memory 记下的是“模型和用户之间的事情”，RAG 查的是模型不知道的事情。

---

问题5: **State 和 Memory 的区别**是什么？

答：
State 是LLM在调用工具的过程中产生的中间状态，比如："用户/任务过程信息"。类似函数的局部变量，任务结束后会丢失。

Memory 是类似数据库：跨轮次，跨会话长期保留的信息。
